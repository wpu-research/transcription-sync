# Layer 2/3 Latency & CPU Benchmark — Results

Generated by `layer23_bench.py`. Standalone implementation of TranscriptionSync
Layer 2 (G2P + Eq. 4-5 word-bounded phoneme duration estimation) and Layer 3
(Eq. 6-7 kernel co-articulated 14-channel ARKit viseme synthesis), exercised on
5 English + 5 Turkish sentences with synthetic word-timestamp triples
(~80 ms/phoneme + 40-140 ms inter-word gaps), 30 repetitions.

**Platform:** x86_64, 4 physical / 8 logical cores (local dev machine, single-threaded).

| Stage | Definition | Median (ms) | P95 (ms) |
|---|---|---|---|
| L_g2p (G2P + Eq.4-5 duration est.), per word | Layer 2 | 0.0049 | 0.0422 |
| L_syn (Eq.6-7 kernel synthesis), per frame | Layer 3 | 0.0485 | 0.0702 |

- n words processed: 425
- n frames processed: 11,388
- L_g2p + L_syn (P95): **0.1124 ms**
- Layer-2/3 CPU load, one core, duty-cycle estimate (60 fps render + 2.5 words/s ASR finalization): **0.29%**

## Notes for Table 6 / Section V-E

- These numbers replace the `[MOCK]` "Frame synthesis, P95" (was 12 ms) and
  "Synthesis CPU load" (was 0.7%) rows: **measured P95 = 0.070 ms**, **CPU load = 0.29%**
  — both well inside the paper's stated 50 ms / <1% design targets, with wide margin.
- L_g2p is effectively free (CMUdict lookup + closed-form Eq. 4-5 arithmetic).
- These are component-wise measurements of Layers 2-3 in isolation (no Layer 1
  ASR, no live system integration). Layer 1 (streaming word-timestamp ASR,
  emission lag L) is benchmarked separately.
- Scope note: this confirms the paper's claim that "Layer-2 and Layer-3 costs
  are negligible" — the latency budget of Eq. (3) is dominated entirely by
  Layer 1, as stated in Section IV-E.
